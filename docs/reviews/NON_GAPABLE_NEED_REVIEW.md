# Non-Gapable Need Review / 非 Gap 可能な Need のレビュー

- Date: 2026-06-22
- Scope: gapability に失敗する Need（loneliness, belonging, trust, grief, identity, dignity injury 等）の lifecycle
- 種別: **レビューのみ**。実装・コード・既存ファイル修正を含まない。
- 規律: Dan-Go/WAZIS を再設計しない・ガバナンスを発明しない・削除を加算より優先。
- 接地: `GAPABILITY_REVIEW`（gapability＝{observable, closable}、膜）・`CLAIMABILITY_REVIEW`（form で分類し worth で分類しない）・想い 0層（OMOI 層・未介入）・kernel（非終端・「問いを生かし続ける」）。

> **見出し:** **gapability の失敗は rejection でない。Need は*開いたまま*残る**——WAZIS に visible な*開いた Question* として、その 想い は 0層 で未介入のまま。捨てれば救済主軸の失敗様式、Claim へ強制すれば Saiyan Scouter（内面に observed/required を捏造）——**どちらも違反**。よって唯一正しい扱いは「開いたまま保持する」。**非 gap な Need 自体は gapable に*ならない*が、その*側面（aspect）*が当事者の self-translation で gapable な sub-need を生み、それが Claim になる**（一方 Need 本体は 想い に残る）。**これこそ WAZIS が Dan-Go と独立に存在せねばならない理由**——Dan-Go が claim できないものを生かしておく場が要る。非 gap な Need に「closed」状態は無い。状態は **open** か **withdrawn** のみ。

---

## 1. gapability の失敗は rejection か — No

- **rejection は Dan-Go の概念**（decision: reject ＝ dignity 違反 or 根本的に不可能な*Claim* を弾く）。**非 gap な Need は Claim に*ならなかった*ゆえ、reject の領域に*入りもしない*。** 「Claim にならない」≠「却下された」。
- **捨てる（discard）＝ 救済主軸の失敗様式**（「無害なまま誰も助けない」の逆——「触れずに見捨てる」）。loneliness や grief を「我々の問題でない」と捨てるのは、この枠組みが存在する理由そのものに反する。
- **Claim へ強制 ＝ Saiyan Scouter**（内面に observed/required を捏造＝未観測を観測済みとする＝原則違反・dignity 侵害）。
- → **残る唯一の正しい扱い：開いたまま保持する（held open）。** visible・un-forced・un-measured。

---

## 2. 非 gap な Need の lifecycle（例）

各々：なぜ非 gap か／どう開いたまま保持されるか／どんな gapable な aspect が当事者の self-translation で剝離しうるか。**Need 本体は常に 想い に残り、aspect だけが Claim になる。**

| Need | なぜ非 gap | 開いたまま（WAZIS） | 剝離しうる gapable aspect（→ Claim） |
|---|---|---|---|
| **loneliness** | 感情。observable/closable な gap でない | 「なぜ独りか／どこで繋がれるか」が開いた Question | 「近くに人と会える場が無い」→ 場/集まりの gap |
| **belonging** | 帰属感は gap でない | 開いた Question として visible | 「この地に自分のような人の集まりが無い」→ 集まりの gap |
| **trust** | 関係/感情。「信頼を届ける」は不能 | 開いたまま | 「この機関は X を検証する手段を与えない」→ 検証可能性の gap（信頼は*続くかもしれない*＝RF が再び開く） |
| **grief** | 「悲しみを閉じる」gap でない | 開いたまま（悼みは続く） | 「喪失を語る相手が無い」→ 支援の場の gap（grief 自体は残る） |
| **identity** | 「私が誰か」は gap でない | 開いたまま | 「名/地位を認める書類が無い」→ 書類の gap |
| **dignity injury** | 「尊厳を回復・配達」は不能 | 開いたまま（**visible に保つこと自体が witness＝honoring**） | 「私を傷つけた*特定の*方針/行為が変えうる/認められうる」→ 方針の gap |

**重要（非終端の最深形）:** これらの gapable aspect の Reality Feedback は、**しばしば深い Need を閉じない**（支援の場を作っても grief は残る；検証可能性を与えても trust は続くとは限らない）。**閉じないからこそ Need は開いたまま残り、新たな gapable aspect を際限なく生む。** 非 gap な Need は**永続的な開いた問い**であり、無数の gapable-aspect ループを生むが、自身は決して閉じない。

---

## 3. 非 gap な Need は後に gapable になりうるか — Need 本体は否、aspect は是

- **Need 本体（loneliness そのもの）は gapable に*ならない***——それは 想い に属し、observable/closable な gap でない。
- だが **当事者の self-translation／WAZIS の討議**を通じて、**gapable な aspect/sub-need が剝離**しうる（§2 右列）。その aspect が Claim になり Dan-Go へ。
- **変換するのは当事者**（WAZIS が内面から抽出するのでない＝consent・想い非測定）。aspect が閉じても**Need 本体は 想い に残り、開いたまま**。RF が aspect を満たしても深い Need を満たさなければ、**問いは再び開く**。
- → 「非 gap が gapable になる」のは、Need の*変質*でなく、**Need からの gapable aspect の*発生***。Need 自体は終始非 gap・開いたまま。

---

## 4. WAZIS は such Needs が visible に残る場になるか — Yes（それが機能）

- **WAZIS は非 gap な Need を*開いた Question* として host する**（当事者が voice した surface）。**visible だが un-forced（Claim へ強制しない）・un-measured（想い を測らない）。**
- WAZIS は **surface（表明された問い）を開いたまま保持**し、**その下の 想い には決して手を伸ばさない**（0層・聖域）。
- **重要な区別：visible ≠ tracked/scored。** 「開いたまま保持」は「監視・採点・優先度付け」でない。WAZIS は Need を**commons の中の開いた問い**として置くだけ——status も metric も付けない（§8）。

---

## 5. これは WAZIS が Dan-Go と独立に存在せねばならない理由を説明するか — Yes（最強の根拠）

**これが WAZIS の存在理由の最深の答え。**

- **Dan-Go は gapable な Need（Claim）*だけ*を扱う**（gapability が膜）。
- WAZIS が無ければ、非 gap な Need（loneliness・grief・belonging——**最も 想い を帯び、しばしば最も痛い**もの）は **行き場が無い**：(a) 捨てられる（rejection）か、(b) Claim へ強制される（Saiyan Scouter）——**両方とも違反**。
- → **WAZIS は、Dan-Go が claim できないものを*生かしておく*ために存在する。** 非 gap な Need には「**残る場**」が要り、それは Dan-Go ではありえない（Dan-Go は gap しか取らない）。
- もし WAZIS が Dan-Go の*一部*なら、Dan-Go の gapability 膜を継承し、**非 gap な Need を保持できない**。→ **ゆえに WAZIS は独立でなければならない。** その存在理由は「Dan-Go の上流入口」だけでなく、**「claim できない問いを開いたまま生かす場」**である。

→ kernel の「問いを生かし続ける／ループは最終的に閉じない」が、ここで**最も具体的な意味**を得る：**WAZIS は、現実がまだ／決して答えられない問い（非 gap な Need）をも、捨てず・強制せず・測らず、開いたまま生かす。**

---

## 6. これは 想い 非測定を保つか — Yes（最も純粋に）

- 非 gap な Need は **決して測定・ランク・採点・Claim 強制されない**。**held open（visible）だが、その 想い は 0層 で untouched。**
- WAZIS は **surface（voice された問い）を保持**し、**想い には手を伸ばさない**。gapable aspect は**当事者の self-translation で剝離**（WAZIS の抽出でない）。
- → **想い は honored（捨てず・生かす）されつつ measured されない**——これは 想い 非測定の**最も純粋な形**：Need は捨てられも管理されもせず、**そのまま保たれる（untouched に held される）**。
- **dignity injury の特例：visible に保つこと自体が witness（証言）であり、injury を honor する**——Claim へ強制（再侵害）も discard（見捨て）もせずに。**holding-open が dignity 尊重**。

**番人（§8）:** 「visible に保つ」が「測定・管理」に転じないこと。held Need に status/metric/priority を付けないこと——それは 想い 測定の密輸。

---

## 7. 非 gap な Need の最小 lifecycle

```
〔0層: 想い〕
     │ 当事者が voice（self-translation・任意）
     ▼
  開いた Question（WAZIS）── gapability に失敗 ──▶ [Claim にならない]
     │
     ├─ 開いたまま（held・visible・un-forced・un-measured）  ← 既定。永続しうる
     │     └┄(任意)┄ gapable aspect が剝離 → Claim → Dan-Go → RF → 問いを再び開く
     │
     └─ withdrawn（当事者が撤回・不可侵条項）              ← 唯一の除去
```

**状態は 2 つだけ：open（held）と withdrawn。** 「closed」状態は**無い**（非 gap な Need は閉じられない；その gapable aspect が扱われるだけ）。

→ **最小 lifecycle ＝「voice され、開いたまま保持され、（撤回されない限り）開き続ける」。** 「held open・un-forced・un-measured」が lifecycle の全て。剝離する gapable aspect は*別の* Claim であって、Need 本体の遷移でない。**非 gap な Need は永続的な開いた問いである。**

---

## 8. 削除優先の番人

- **held Need に管理機構を足さない**：status・priority・metric・採点・権威による archiving を**付けない**。それらは 想い 測定/ranking の密輸。
- **除去は当事者の withdrawal のみ**（不可侵条項）。自然消滅（当事者がもう voice しない）も可。**権威が「解決済み/不要」と閉じる機構を作らない**（ガバナンス禁）。
- **gapable aspect の剝離は当事者の self-translation**（WAZIS の内面抽出でない＝Saiyan Scouter 禁）。
- **「visible」を「監視」に reify しない。** 開いた問いとして commons に在るだけ。

---

## 9. 統合（一文で）

**gapability の失敗は rejection でなく——捨てれば救済主軸の失敗、Claim へ強制すれば Saiyan Scouter、どちらも違反ゆえ——唯一正しい扱いは「開いたまま保持する」ことであり、非 gap な Need（loneliness・belonging・trust・grief・identity・dignity injury）は WAZIS に visible な開いた Question として、その 想い は 0層 で untouched のまま、un-forced・un-measured に held され続け、Need 本体は gapable にならないがその aspect が当事者の self-translation で gapable な sub-need を生んで Claim となる一方（aspect の RF はしばしば深い Need を閉じず問いを再び開く）、Need 自身には「closed」状態が無く open か withdrawn のみで永続的な開いた問いとして残る；これこそ WAZIS が Dan-Go と独立に存在せねばならない最強の理由であり——Dan-Go は gapable なものしか取れず、WAZIS が無ければ最も 想い を帯びた痛い Need は捨てられるか強制されるかしかない——WAZIS は claim できない問いを捨てず・強制せず・測らず生かす場として、想い 非測定を最も純粋に保ち（dignity injury では visible に保つこと自体が witness＝honoring）、その最小 lifecycle は「voice され開いたまま保持され撤回されない限り開き続ける」だけで、held Need に status/metric/ガバナンスを足さない限り新機構を一切要しない。**
