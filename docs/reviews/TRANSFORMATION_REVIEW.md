# Transformation Review / 変換レビュー

- Date: 2026-06-22
- Scope: ループ中間部（既往レビューの「Reality Action / 現実作用」）は *thing* でなく *transformation* か、を検証する
- 種別: **レビューのみ**。実装・コード・既存ファイル修正・新プロトコル・新教義を含まない（本書の新規作成のみ）。
- 規律: **新しい層・メタプロトコル・grand unified theory を作らない。** 既存の Constitution/Spec/Reviews に暗に在るなら、そう言う。
- 判定: **Kill Test**（除去で identity が変わる概念だけ load-bearing）＋ **Reification Test**（名を消して何も壊れなければ、それは新 entity でなく lens）。
- 参照: [WAZIS_KERNEL_REVIEW.md](WAZIS_KERNEL_REVIEW.md)（橋＝experimentability）・[META_LOOP_REVIEW.md](META_LOOP_REVIEW.md)・[WAZIS_DANGO_BOUNDARY_REVIEW.md](WAZIS_DANGO_BOUNDARY_REVIEW.md)・[WAZIS_SPEC.md](../history/WAZIS_SPEC.md)（Binding）

> **一行結論:** **Yes——中間部は『もの』でなく『変換（transformation）』である。** ただしこれは新概念ではない。**kernel review が既に『橋（experimentability）』として、Spec が『Binding』として名指していた load-bearing な遷移**そのものを、より正確な動詞で呼び直すだけ。「Reality Action」は *過程を物に名詞化し*、しかも *WAZIS は現実に触れない* という境界を曖昧にする点で、**軽度に misleading**。中間部は **node（頂点）でなく edge（矢印）**：問いを「現実が答えられる形」へ変える操作であり、その完了が Reality Feedback である。

---

## 0. 二つの test を先に当てる

**対象:** 「中間部は transformation である」という主張。

- **Kill Test:** 変換（問い→現実が答えうる形）を取り除くと → 現実が応える対象が消え → Reality Feedback が起きず → ループが回らず → discussion/forum に崩落。**→ load-bearing。** ただし*これは kernel review の「橋」と同一物*。
- **Reification Test:** 「Transformation」という**名**を消すと → 実験化・Execution・PR・支援活動・Binding は**依然として起きる** → 何も壊れない。**→ よって「Transformation」は新 entity でなく、既存の load-bearing 操作への正確な名（lens）。**

両 test の合致した評決: **名指される操作は load-bearing かつ既出。「Transformation」という語は、その操作の正確な呼称であって、新しい層ではない。** 以下これを精密化する。

**重要な制限（自らに課す）:** 「すべては変換である」という**広い**主張は採らない——それは何も足さず Reification Test に落ちる（grand unified theory の失敗様式）。load-bearing な主張は**狭い**: 「*ループ中間部*は、問いを現実応答可能な形へ変える変換であり、それ無しに Reality Feedback はありえない」。

---

## 1. 中核の発見 — 中間部は頂点でなく矢印

meta-loop review は中間を「③現実作用（試す）」と、**5節点の一つ（頂点）**として描いた。本補正はそれを正す:

```
旧（misleading）:   ②問い ── ③現実作用（thing/node） ── ④Reality Feedback
新（正確）:          ②問い ──────[ transform → 現実応答可能な形 ]──────▶ ④Reality Feedback
                                        （edge/arrow・過程）
```

中間は**頂点（もの）でなく辺（変換）**である。Experiment Candidate / Claim / Pull Request / 支援活動は、その変換が**通過点で残す中間生成物（made-answerable form の凍結スナップショット）**であって、中間部の本質ではない。本質は **transforming（変えること）**。

→ 「Reality Action」は、この**矢印を頂点として誤描した**。だから物のように見え、reify を誘う。

---

## 2. Q1 — Transformation が消えると何が消えるか

**問いと現実の応答能力との結合が消える。** 連鎖して:
- 問いが「現実が答えうる形」にならない → 現実に応える対象が無い → **Reality Feedback が生じない** → ループが閉じず開かず → 現実が裁定できない → **WAZIS の identity（討議でなく現実が裁定）が不可能化** → forum へ崩落。

これは kernel review §1 の「橋（experimentability）が無いと現実が応える対象が存在しない」と**字義通り同一**。だから消えるのは**新しい何かでなく、既に最も load-bearing と判定済みの『橋』**。Transformation = その橋の動詞形。

---

## 3. Q2 — Transformation は thing か process か perspective か

二層で答える:

- **個別の中間部（実験化・Execution・PR・支援活動）は process（操作）。** 動詞「変換する」が正確。射（morphism）: `問い → 現実応答可能な形`。
- **「中間部はすべて変換だ」という一般名は perspective（視座）。** 異なる中間部が一つの*役割*を共有すると認識する読み。
- **いずれの層でも thing ではない。** 「a transformation」を repo 内に指させない——指せるのは Experiment Candidate / Claim / PR（＝出力物）であって、変換そのものではない。

→ **instance では process、一般化では perspective、決して thing でない。** この二重性が Reification Test を通す根拠: 個々の操作は実在の load-bearing 操作、一般カテゴリは lens（新 entity でない）。

---

## 4. Q3 — Dan-Go は変換として機能するか

**Yes。** Dan-Go は Claim（提案された遷移＝「これは起こせるか」という半ば開いた問い）を、Contribution→Execution を通じて**現実が応えうる deed** へ変換する。Claim → Execution → 現実が応える（executed/partial/failed）。Dan-Go の Claim→Contribution→Execution 機構全体が、一つの（精緻で・人間承認を伴い・調整された）**変換**。

ただし二重性（boundary review と整合）: Dan-Go は**それ自身が完全なループ**でもある（自前の RF を持つ）。だから——
- 単体で見れば: 完全なループ。
- 大きなループの中間（Binding）として見れば: WAZIS の実験を**現実応答可能な execution へ変換する一段**。

連結時、中間部は**変換の合成**になる（§5）。

---

## 5. Q4 — WAZIS は変換として機能するか

**Yes——これは kernel そのもの。** WAZIS は Question を Experiment Candidate（現実応答可能な形）へ変換する。「問いを実験へ変えて現実に裁定させる」＝まさに変換。

重要な分担:
- **WAZIS は変換の前半を担う**: 問い → Experiment Candidate（*原理上*答えうる形にする）。**だが現実には触れない**（boundary review の明線）。
- **実装先（Dan-Go 等）が後半を担う**: Experiment Candidate → 実際の deed → Reality Feedback（*現実に*submit する）。

→ 中間部は **二つの可換な変換段の合成**: `WAZIS（答えうる形にする）∘ 実装先（現実に付す）`。これは「WAZIS 上流・実装先下流の composable peers」（boundary review）と一致し、**新層を足さない**。なお「Reality Action」が WAZIS にも掛かると、WAZIS が現実に action するかに読めて境界を侵す——「Transformation」の方が安全（§7）。

---

## 6. Q5 — NPO/OSS/研究/自治体/共同体は同型の変換か

**同じ *type*、異なる *instance*。** すべてが「問い/提案 → 現実応答可能な形 → Reality Feedback」という同一の射を共有し、(a) 中間生成物 と (b) 触れる現実の媒体 が違うだけ:

| 実装先 | 入力 | 変換（made-answerable form） | 現実が答えるもの |
|---|---|---|---|
| WAZIS | Question | Experiment Candidate | （実装先へ委譲） |
| Dan-Go | Claim | Execution（人間承認） | executed? 誰か助かった? |
| OSS | Issue | Pull Request → CI/merge/利用 | 動くか? 採用されるか? |
| NPO/共同体 | Proposal | 支援活動 | 誰か助かったか? |
| 研究 | Question/仮説 | 実験/研究 | 再現/確証/反証? |
| 自治体 | Proposal | パイロット/施策 | 指標が改善したか? |

→ **同型（同 type）。そしてこれは WAZIS に既出**: 各々は **Binding**（Experiment Candidate を各実装先の現実応答可能な形へ写すアダプタ）にほかならない。**Binding ＝ 変換アダプタ**。「同じ type の変換」は、Spec の「実装中立な Binding インターフェース」として**既に符号化済み**。

---

## 7. Q6 — すべてに共通する最小構造はあるか

**ある。一本の射:**

```
開いた入力 ──[ 現実が答えうる形へ変換 ]──▶ 現実が応える ──▶ Reality Feedback
```

最小で言えば: **「問いが、現実によって答えられうるものにされる」**。共通構造 ＝ この *made-answerable* の操作。これは kernel review の **experimentability**（現実応答可能性）を、*静的な性質*でなく *その性質を付与する操作*として見たもの——**同一物の動詞形**。

→ 最小共通構造は **experimentability-as-operation ＝ transformation**。既出（kernel review の橋）。

---

## 8. Q7 — 「Reality Action」は実際 misleading な名か

**軽度に Yes。三つの理由:**

1. **過程の名詞化。** 「action」は*もの/領域*に読め、矢印を頂点に誤描し、reify を誘う（§1）。実体は edge（変換）。
2. **doing への偏り。** 「action」は *doing*（Dan-Go の極）を強調し、*asking を答えうる形にする*ケース（WAZIS の実験化・研究の study）を過小記述する。実験候補や研究は「現実への行為」というより「問いを試験可能形へ変換」。
3. **境界の曖昧化（最重要）。** 「Reality Action」が WAZIS に掛かると「WAZIS が現実に action する」に読め、**WAZIS は現実に触れない**（boundary review の明線・kernel 不変項）を侵す。**「Transformation」はこれを侵さない**: WAZIS は問いを答えうる形へ*変換*するが現実には触れず、実装先が現実に付す。

ただし「Transformation」単独だと*行き先（現実が答える）*が落ちる。正確には「**現実が答えうる形への**変換、その完了が Reality Feedback」。新語を造らず、この説明形で足りる。

---

## 9. Q8 — ループ中間部の最も単純で正確な記述

> **中間部は、問いを『現実が答えられる形』へ変える変換である——その完了が Reality Feedback。**

最短形:
> **中間部は、問いが現実に答えられうるものにされる場（変換）であって、もの（領域）ではない。**

矢印で:
> `問い ──[現実応答可能な形へ変換]──▶ Reality Feedback`（中間は edge、Experiment Candidate/Claim/PR はその通過スナップショット）。

---

## 10. 既に暗に在るか — Yes

この変換は**既存文書に暗に在る**。新概念ではない:

| 既出の名 | 出所 | 関係 |
|---|---|---|
| **橋（experimentability）** | kernel review §1「不変項を繋ぐ唯一の遷移」 | Transformation の*静的*呼称。今回*動詞*化 |
| **Experimentability は遷移条件** | experiment-driven review | 同上 |
| **Implementation/Experiment Candidate** | Constitution / Spec §1.4 | 変換の*出力物*（現実応答可能形のスナップショット） |
| **Implementation Binding** | Spec §5 | 各実装先への*変換アダプタ*。「同 type」（Q5）の符号化済み |

→ **「Transformation」は新層でも grand theory でもなく、(a) 「Reality Action」の誤り（thing→process, node→edge, doing→made-answerable）を正し、(b) 散在する experimentability / Binding / 橋 を一つの正確な動詞で束ねる *呼び直し* である。** Reification Test 上は lens として合格し、layer としては**立てない**。これは Voice Commons 理論が視座だったのと同様（既存仕様を上書きしない）。

**唯一の実務的含意（推奨・実装でない）:** 既往レビューの語「Reality Action / 現実作用」を、今後は「**問いを現実応答可能な形へ変える変換（transformation）**」と読み替える。これは命名の修正であって、構造の追加ではない。

---

## 11. 統合（一文で）

**ループ中間部は『もの』ではなく『変換』である——問いを、現実が答えられる形へ変える操作であり、その完了が Reality Feedback である。WAZIS はこの変換の前半（答えうる形にする・現実には触れない）を、Dan-Go や NPO/OSS/研究/自治体/共同体はそれぞれ後半（現実に付す）を担う、同じ type の可換な変換段であり、それらは既に Binding として符号化されている。ゆえに「Reality Action」は矢印を頂点と誤描した軽度に misleading な名であり、正しくは『現実応答可能な形への変換』——だがこれは kernel の橋・experimentability・Binding として既に暗に在ったものの呼び直しにすぎず、新しい層・プロトコル・教義ではない。**
