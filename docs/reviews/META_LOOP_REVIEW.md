# Meta-Loop Review / メタループ・レビュー

- Date: 2026-06-22
- Scope: WAZIS と Dan-Go が共に「より大きなループ」を成すかを検証する
- 種別: **レビューのみ**。実装・コード・既存ファイル修正を含まない（本書の新規作成のみ）。
- 規律（ユーザー指示）: **新しい教義を発明しない・新しいプロトコルを発明しない・新しい層を無理に作らない。** 判定は kill-test（除去すると system の identity が変わる概念だけが load-bearing）。
- 参照: [WAZIS_CONSTITUTION.md](../../WAZIS_CONSTITUTION.md)（想いとの関係 / 前提層0層図）・[WAZIS_KERNEL_REVIEW.md](WAZIS_KERNEL_REVIEW.md)・[WAZIS_DANGO_BOUNDARY_REVIEW.md](WAZIS_DANGO_BOUNDARY_REVIEW.md)・Dan-Go 研究ノート `DANGO_OMOI_LAYER_REVIEW.md`（想いを0層に置く同型図）

> **一行結論:** ループは**実在する。が、新しくない。** それは WAZIS Constitution と Dan-Go の OMOI レビューが**既に描いている** 想い↔現実の循環そのものであり、WAZIS と Dan-Go は「合わさってより大きなループになる」のではなく、**元から在る一つのループの『現実作用』の弧を、二通りに歩く**だけである。よって本書は新層を立てない。**メタループは layer（層）でなく lens（視座）**である——名指しはするが、reify はしない。

---

## 0. 方法と、reify への番人

二段の規律を置く:

1. **kill-test:** 概念は、除去で identity が変わるときだけ load-bearing。
2. **anti-reification（番人）:** 「名指す」ことは「作る」ことではない。あるループを**記述できる**ことと、それが**新しい load-bearing な層として存在する**ことは別。番人テスト: *「メタループ」という名前を消したら、何かが壊れるか?* 壊れなければ、それは層でなく視座である。

この二つを通すと、誇張（grand meta-protocol）への滑落を防げる。Dan-Go 最上位原理が戒めた「新たな最上位管理レイヤを reify しない」と同じ規律。

---

## 1. 合成すると、何が起きるか（事実の追跡）

WAZIS と Dan-Go を実際に繋ぐと:

```
〔0層〕想い ──self-translate──▶ 問い ──討議/実験──▶ Experiment Candidate
                                                        │ Binding（map）
                                                        ▼
                                              Claim ──Contribution──▶ Execution（人間承認・現実の行為）
                                                        │
                                              Reality Feedback（現実の観測）
                                              ├─ Dan-Go は grade と読む（Claim 完了・trust 更新）
                                              └─ WAZIS は oracle と読む（新しい問いを開く）
                                                        │
                              新しい問い ◀──────────────┘     …そして「誰か助かったか」は想いの aim へ帰着
```

観察:
- **これは円環である**: 問い → … → Reality Feedback → 新しい問い → 問い。だが**それは WAZIS が既に持つループ**である（kernel review §1）。
- **Dan-Go もそれ自身のループを持つ**: Claim → Execution → RF →（"informs future claims of similar type", MUJIN_PROTOCOL Phase 4）→ 次の Claim。
- 合成とは、**二つのループが Reality Feedback（現実）という節点を共有して噛み合う**こと。新しい第三のループが生えるのではない。**蝶番（RF）を共有する二つの歯車**。

→ だから「より大きなループ」は、**両者より上の新層**ではなく、**両者より根源的な、既に在る循環**——WAZIS も Dan-Go も、その『現実作用』の弧を埋めているだけ。次節以降がこれを精密化する。

## 2. Q1 — そのループの最小で正確な記述

最小ループを kill-test で削り出すと、**5節点**が残り、どれも外せない:

```
①想い(源・aim) ─②表明(問い) ─③現実作用(試す) ─④Reality Feedback ─⑤帰着/新しい問い ─▶①へ
```

| 節点 | 外すと | 判定 |
|---|---|---|
| ① 想い（源かつ aim） | aim（助かる方向）を失い、ただの汎用 feedback 系に | load-bearing |
| ② 表明＝問い | 想いは表明されない限り作用できない（self-translation が唯一の honest な入口） | load-bearing |
| ③ 現実作用（実験/Claim/Execution） | 現実に届かず RF が生じない | load-bearing |
| ④ Reality Feedback | 円環が閉じず・学ばず、ただの表現に | load-bearing（蝶番・§5） |
| ⑤ 帰着/新しい問い | 線形化し循環の identity を失う | load-bearing |

**最小で正確な記述（一文）:**
> **想いが、測られないまま、問いとして表明され、現実で試され、その応答（Reality Feedback）が想いへ帰り、次の問いを開く循環。**

最短形:
> **想いが、測られずに、現実と対話する循環。**

**決定的に重要な点:** この最小記述に **WAZIS も Dan-Go も登場しない**。両者は③「現実作用」の弧の**埋め方**にすぎない（WAZIS が②→③前半、Dan-Go が③後半→④）。**ループは両プロトコルより根源的**で、両者を**含意しない**。これが「新層でない」ことの構造的証拠。

---

## 3. Q2 — 何がループに入るか

ループには**二つの膜（membrane）**があり、入口は二つ:

- **想い側の膜から入るのは『問い』だけ。** 想いそのものは入らない（§7）。当事者の self-translation で生じた**表面（問い）**が入る。想いは測られず、地に留まる。
- **現実側の膜から入るのは『Reality Feedback』。** 現実の観測がループへ戻る。

ループ内部の動き（視座・objection・contribution・実験）は**入るもの**ではなく**内部の運動**。外から越境して入るのは、この二つ（問い／RF）だけ。

→ **入るもの: 問い（想い側）と Reality Feedback（現実側）。** 想い自体は入らない。

---

## 4. Q3 — 何がループから出るか

- **現実側の膜から出るのは『deed（行為）』** — Experiment Candidate / Claim → Execution が外界へ出て、現実に作用する（誰かが housed/funded される、実験が起きる）。**ループから世界へ真に出ていくのは、この deed とその効果だけ。**
- **想い側の膜から出るものは、測られた何も無い。** ループは想いへ**測定値を預けない**。返るのは「誰かが助かった」という**lived な事実**であって、データではない。
- **問い・feedback は出ずに再循環する**（⑤→①→②）。

→ **出るもの: 現実への deed（と、それが生む助け）。** 想いへは、測定された出力は出ない（出したら測定＝原則違反）。**二つの膜は、想いの非測定と「現実を捏造しない（自採点しない）」という二つの kernel 不変項そのもの**である。

---

## 5. Q4 — Reality Feedback は中心か、単なる遷移か

**遷移（蝶番）であって、中心ではない。** 二つの「中心」概念を分ける:

- **最も load-bearing な節点という意味の中心 →** RF は該当する（kernel review でも最致死）。これは**円周上で最も重要な点＝蝶番（hinge）**。ループが「doing→asking」「現実→想い」へ折り返す枢軸。
- **ループが orbit する hub という意味の中心 →** RF は**該当しない**。ループの aim は**想いの目的（誰かが助かる）**であり、RF はそれに**仕える手段**。

幾何で言えば:
```
        想いの aim（hub・中心）
         ·  ← ループはこれを orbit する
   ②──③──④(RF, 蝶番)──⑤   ← 円周（rim）。RF は rim 上の最重要点
```

**RF は rim 上の蝶番、想いの aim は hub。** RF を「中心」と呼ぶと、system が**「feedback を最適化する」方向へ漂流**する——「誰かを助ける」でなく「指標を上げる」へ。これは保存済み評価フレーム（救済主軸・TTFR）が名指す失敗様式。だから**RF を中心に祭り上げてはならない**。RF は**最も load-bearing な遷移**であり、**中心ではない**。

---

## 6. Q5 — Question は真の始まりか

**入口（threshold）ではあるが、起源（origin）ではない。** 三点:

1. **想いが先行する。** 問いは想いの self-translation。問いの手前に想いがある（§7）。
2. **ループに始まりは無い。** どの「新しい問い」も、前周の RF か想いからの新たな汲み出しの**続き**。線形の「始点」は、円環に押し付けた虚構。
3. **ゆえに:** Question は**ループへ最初に入る表面（threshold）**として load-bearing だが、**真の origin ではない**。origin と言えるのは想いだが、想いは**地であって段（step）ではない**（hub であって rim 上の点でない）。

→ **Question = 入口（閾）。想い = 地（源）。だが「始まり」という枠が、そもそもループに適さない。**

---

## 7. Q6 — 想いはループの外か、一部か

**どちらでもない。想いはループの『地（ground）/ hub』である。** 既存文書の通り（WAZIS Constitution「両端で挟むが中に入らない」／OMOI レビュー「源かつ aim、決して中に入らない」）:

- 想いは**源**（問いがそこから汲まれる）であり**aim**（feedback がそこへ帰る）。
- **両端でループを挟む（bracket）が、節点として中に入らない。** 内部で測定・記録・処理されない。
- 幾何では **hub**（ループが orbit する中心）であって、**rim 上の点ではない**。

kill-test: 想いを絵から消す → aim 無き汎用 feedback/実験系へ → identity 喪失。**load-bearing。ただし「入らない地」としてであって、節点としてではない。** もし想いが節点として入れば、測定対象になり原則違反——**「入らないこと」自体が保護**。

→ **想いはループの外でも中でもなく、ループが orbit する hub。触れられるのは二つの膜（self-translation で出、aim として帰る）でだけ。内には決して入らない。**

---

## 8. Q7 — このループは既に Constitution / Spec に暗に在るか、真に新しいか

**既に在る。真に新しくない。** これが本書の最重要判定。

証拠:
- **WAZIS Constitution「想いとの関係（前提層/0層）」**が、この循環を既に図示している: `0層 想い → Question → … → Reality Feedback →（帰着）想いの aim → 前提層へ還る`。
- **Dan-Go `DANGO_OMOI_LAYER_REVIEW.md`** が、**同型の図**を既に描いている: `想い(0層) → self-translation → [dignity/Claim/Question/Objection/Contribution/Execution] → Reality Feedback →「誰か助かったか」→ 想いの aim へ帰着 → 前提層へ還る`。
- 両者は**同じ循環**を、各々の側から描いている。「メタループ」とは、**両者が Reality Feedback という蝶番を共有する点で見たときの、その既出の循環**にすぎない。

**番人テスト:** 「メタループ」という名を消す → 何も壊れない。両プロトコルは依然それぞれ想い+RF を巡る。→ **メタループは新しい load-bearing な層ではない。** load-bearing なのは「WAZIS と Dan-Go は一つの既出循環の二つの弧である」という**認識**であって、その認識を新プロトコルへ reify することではない。

→ **これは Voice Commons 理論が「視座（lens）」だったのと同じ。** 既存の canonical 構造の上に**読み**を重ねるが、仕様を上書きしない。新層を立てれば、想いの前提層を管理対象化する誘惑を呼ぶ（Dan-Go 最上位原理の戒め）。**立てない。**

## 9. Load-bearing 判定のまとめ

| 概念 | ループにおける役割 | load-bearing? |
|---|---|---|
| 想い（hub・源/aim） | ループが orbit する地。測られない | ✅（入らない地として） |
| 問い（threshold） | 想い側の膜の入口 | ✅ |
| 現実作用（実験/Claim/Execution） | rim の弧。WAZIS と Dan-Go が埋める | ✅（機能として。*どちらが*埋めるかは置換可） |
| Reality Feedback | rim 上の蝶番（最重要遷移） | ✅（中心ではない・§5） |
| 帰着/新しい問い | 円環を閉じ再び開く | ✅ |
| **WAZIS / Dan-Go（個別プロトコル）** | ③の弧の埋め方 | ❌ ループには非本質（兄弟・置換可） |
| **「メタループ」という新層/教義** | — | ❌ reify は禁。lens であって layer でない |

**含意:** ループは load-bearing。だが**ループを構成するのは想い・問い・現実作用・RF・帰着であって、WAZIS でも Dan-Go でも「メタプロトコル」でもない**。WAZIS と Dan-Go は、この既出ループの③を歩く**二つの可換な方法**。

---

## 10. 統合（一文で）

**WAZIS と Dan-Go は合わさってより大きなループになるのではない——両者は、Constitution と OMOI レビューが既に描いていた一つの循環『想いが、測られぬまま、問いとして表明され、現実で試され、その応答が想いへ帰り、次の問いを開く』の、現実作用の弧を二通りに歩いているだけである。このループで Reality Feedback は最も load-bearing な蝶番だが中心ではなく、中心（hub）は触れられぬ想いの aim（誰かが助かる）であり、問いは入口であって起源ではなく、想いは外でも中でもなくループが orbit する地である。ゆえに新しい層は無い。あるのは、既に在ったものの認識だけである。**
