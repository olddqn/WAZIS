# Need Maturation Review / Need の成熟レビュー

- Date: 2026-06-22
- Scope: 非 gap な Need は後に gapable になりうるか。「maturation（成熟）」とは何か
- 種別: **レビューのみ**。実装・コード・既存ファイル修正を含まない。
- 規律: Dan-Go/WAZIS を再設計しない・ガバナンス/スコアを足さない・削除を加算より優先。
- 接地: `NON_GAPABLE_NEED_REVIEW`（held open・aspect が剝離・状態は open/withdrawn のみ）・`GAPABILITY_REVIEW`（gapability＝{observable, closable}・binary）・想い 0層・kernel（RF・非終端）。

> **見出し:** **Need は「成熟（ripen）」しない**——loneliness や grief は as-is で完全・valid で、閉じる先も「より良くなる」先も無い。「maturation」が正確に名指すのは Need の熟成でなく、**gapable な aspect の*出現（surfacing）***——当事者が WAZIS の生きた空間（reflection・discussion・reality feedback・time）の中で gapable な側面を*自ら articulate* する binary な event であり、起きないこともある。**元の Need は aspect が現れても開いたまま**（非 gap・未測定）。maturation は **self-translation（当事者の主体性）＋ reflection/discussion/RF/time（WAZIS が*提供する条件*）の組み合わせ**で生じ、**WAZIS が Need に*する*ことではない**。**これが WAZIS を storage で置換できない理由**：storage は inert に*保管*するだけで maturation の条件（生きた接触）を欠く。WAZIS は*生かしておく*（条件に接触させ続ける）。**番人：maturation は binary・un-forced・un-measured。stage でも score でもパイプラインでもない。**

---

## 1. Need は成熟するか — 精密な Yes/No

- **No（Need 自体）:** Need は ripen/progress/「より valid に」なるのでない。loneliness/grief は最初から完全・valid——「未成熟」でない（そう読むと Need を*測り・貶める*＝想い 非測定違反）。Need には closure も「進捗」も無い（NON_GAPABLE：open/withdrawn のみ）。
- **Yes（gapable aspect の出現）:** 時間と接触の中で、**gapable な aspect が articulable になる**。これが「maturation」の正確な所在。
- → **削除優先の reframe:** 「この Need はどれだけ成熟したか」（Need を測る＝禁）を問わず、**「gapable な aspect が現れたか」（binary・aspect について）**だけを問う。

「maturation」は——「Reality Action」が edge を node と誤描したように——**Need の熟成と読むと misleading**。正確には **aspect の surfacing**。

---

## 2. maturity ＝ gapable aspect の出現か — Yes（それが定義）

- maturation ＝「gapable な aspect が articulable になる event」。**Need の property/score でなく、aspect の出現（event）。**
- それは **gapability test（{observable, closable}）を、当事者が articulate した aspect に当てる**こと——既存の binary 判定。新概念でない（Reification Test：「maturation」を消しても、aspect は出現し gapability で判定される——何も壊れない＝lens）。
- → **maturity は Need の目盛りでなく、aspect の有無（binary）。** スコア化しない。

---

## 3. aspect が現れても元の Need は開いたままか — Yes（NON_GAPABLE 再確認）

- aspect は**別個の Claim**（→ Dan-Go）。**Need は WAZIS で開いたまま**（非 gap・想い 0層）。
- **aspect の RF はしばしば深い Need を閉じない**（支援の場 → grief は残る）。ゆえに **maturation ≠ resolution**。aspect が次々現れ扱われても **Need は full に open でありうる**。
- → **maturation は Need を closure へ「進める」のでない。** Need から*別の claimable な物*が生まれるだけ。Need は永続的な開いた問い。

---

## 4. WAZIS は maturation が起きる場か — Yes（土壌であって庭師でない）

- WAZIS は **maturation の*条件*を提供する空間**：(a) 開いたまま保持（visible・un-forced・un-measured）、(b) deliberative（討議・counter-question）、(c) reality feedback の接続（過去ループの観測が戻る）、(d) 無期限の time（締切なし）。
- だが WAZIS は **maturation を*する*のでない**。aspect を articulate する**主体は当事者**（self-translation）。**WAZIS が内面から aspect を抽出すれば Saiyan Scouter（禁）。**
- → **WAZIS は土壌（条件）、当事者は種（主体性）。** Need は WAZIS の中で「会話で問いが深まる」ように熟す——WAZIS が*処理*するからでなく、**開いたまま reflection/discussion/RF/time に*接触*させ続ける**から。

---

## 5. maturation は何で生じるか — 組み合わせ（self-translation が irreducible）

| 駆動 | 役割 | WAZIS は |
|---|---|---|
| **self-translation** | **当事者が aspect を articulate する主体性（irreducible・核）** | 場を開くだけ（抽出しない） |
| reflection | 当事者が問いに立ち返る | 開いたまま保持（time を与える） |
| discussion | 他者の視座/counter-question が aspect を浮かす | Forum（投票/裁定なし） |
| reality feedback | 過去の aspect-loop の RF が次の aspect を示唆 | loop を接続（kernel） |
| time | 急がせない。aspect は熟すまで現れない | 無期限に開く（非終端） |

**例（駆動は case ごとに異なる）:**
- **loneliness:** time＋reflection → 「近くに人と会える場が無い」（場の gap）。
- **grief:** reality feedback（前ループ）＋time → 「同じ喪失を経た人と話したい」（支援の場の gap）。
- **belonging:** discussion（他者の視座）→ 「この地に自分のような人の集まりが無い」（集まりの gap）。
- **trust:** reality feedback（破られた約束の観測）→ 「彼らの主張を検証する手段が無い」（検証可能性の gap）。
- **dignity injury:** reflection＋discussion → 「私を傷つけた*特定の*方針が変えうる/認められうる」（方針の gap）。

→ **組み合わせ。self-translation が主体性として irreducible、reflection/discussion/RF/time は WAZIS が提供する*条件*。** いずれも WAZIS が Need に*する*ことでなく、**当事者と共に・WAZIS の生きた空間で**起きる。

---

## 6. これは WAZIS を storage で置換できない理由を説明するか — Yes（中心）

**storage（DB・archive・issue tracker・knowledge base）は Need を*保管*するが inert である。**

- storage は **reflection を促さない・discussion を持たない・reality feedback を接続しない・time を「生きた」ものにしない・self-translation を誘わない**。
- 保管された Need は**ただ座っている**。**maturation の条件が無い**ため、gapable aspect が出現しない。storage は Need を*保つ*が**殺す（inert 化する）**。
- **WAZIS は生きた commons**：loop 接続（RF）・deliberative（Forum）・無期限に開く。Need を **maturation の条件（reflection/discussion/RF/time）に*接触*させ続ける**。
- → **「keep alive」≠「store」。** NON_GAPABLE の「claim できない問いを生かす」は、ここで精密化される：**「生かす」＝「maturation の生きた条件に接触させ続ける」**——storage には不可能。**WAZIS の kernel（RF ループ）こそ、storage が欠き maturation を可能にするもの。** 倉庫は保つ、WAZIS は生かす。

---

## 7. 最小 lifecycle

```
〔想い 0層〕
   │ 当事者が voice（self-translation・任意）
   ▼
Open Question（WAZIS）──┐  held open・visible・un-forced・un-measured  ← Need は*ここに永続*（open/withdrawn のみ）
   │ ▲                 │  〔生きた条件：reflection · discussion · RF · time〕
   │ │                 ▼
   │ │   maturation ＝ gapable aspect が articulable になる event（当事者・binary・起きないこともある）
   │ │                 │
   │ │                 ▼
   │ │   Gapable aspect（別個）→ Claim → Dan-Go → Reality Feedback
   │ └─────────────────┘  RF が Open Question の空間へ戻り、次の maturation を養う
   ▼
（撤回されない限り Open のまま・永続）
```

**要点:**
- **Need は「Open」を決して離れない。** maturation は Need が*通過する stage* でなく、Open のまま**そこから aspect が*生まれる* event**。
- **aspect は別個の Claim**（Need の遷移でない）。Need の状態は依然 open/withdrawn のみ（closed 無し）。
- **RF は Open Question の空間へ戻り**、次の aspect の maturation を養う（loop）。

→ **最小 lifecycle ＝「Open（永続）から、当事者が生きた条件の中で gapable aspect を articulate したとき、その aspect が別個に Dan-Go へ行き、RF が戻って Need を養う——Need 自身は開いたまま」。** maturation は Need の stage でなく、Open から生じる event。

---

## 8. 削除優先の番人

- **maturation を stage/score/パイプラインに reify しない。** 「成熟度 0–100」「maturation 待ち行列」「promote する管理」を作らない——想い/Need の measurement・ranking の密輸。**maturation は binary な event（aspect が現れたか）。**
- **self-translation は当事者のもの。** WAZIS が内面から aspect を抽出すれば Saiyan Scouter（禁）。WAZIS は条件を提供するだけ。
- **「生きた条件」を「監視」に reify しない。** reflection/discussion/RF/time は commons の自然な性質であって、Need ごとの追跡指標でない。
- 除去は当事者の withdrawal のみ。権威が「成熟させる/閉じる」機構を作らない（ガバナンス禁）。

---

## 9. 統合（一文で）

**Need は ripen しない（loneliness/grief は as-is で完全・valid で closure も進捗も無い）が、その gapable な aspect が WAZIS の生きた空間の中で——self-translation を主体性の核に、reflection・discussion・reality feedback・time を WAZIS が提供する条件として——articulable になる event を「maturation」と正確に呼べ、それは Need の property/score でなく aspect の出現（binary・起きないこともある）であって、aspect は別個の Claim として Dan-Go へ行き RF が Open Question の空間へ戻って次の maturation を養う一方、元の Need は open のまま（aspect の RF はしばしば深い Need を閉じない＝maturation ≠ resolution、状態は open/withdrawn のみで closed 無し）永続的な開いた問いとして残る；WAZIS は maturation を*する*のでなく Need を maturation の条件に*接触させ続ける*土壌であり、これこそ WAZIS を storage で置換できない理由である——storage は Need を inert に保管して殺すが、WAZIS は loop 接続・deliberative・無期限に開く生きた commons として「保つ」でなく「生かす」——その最小 lifecycle は「Open（永続）から当事者が aspect を articulate したとき別個に Dan-Go へ、RF が戻って Need を養い、Need 自身は開いたまま」であって、maturation を stage/score/ガバナンスに reify しない限り新機構を一切要しない。**
