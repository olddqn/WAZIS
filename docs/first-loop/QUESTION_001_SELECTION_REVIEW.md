# Question #001 Selection Review / 選定レビュー

- Date: 2026-06-22
- Scope: WAZIS の最初の公開ループとなる **Question #001 を選定する**
- 種別: **レビューのみ**。実装・コード・既存ファイル修正を含まない。
- 規律: **WAZIS を再設計しない・機能を足さない・新概念を足さない・削除を加算より優先。** 最初の実ループの選定のみに集中。
- 成功条件: `Question → Reality Feedback → New Question`。**RF の outcome は何でもよい（failure を含む）。**
- 接地: Dan-Go `FIRST_CASE_CANDIDATES.md`（C1–C7、未検証・順不同・組織レベル・個人非接触・安全ゲート済）／`FIRST_REAL_CASE_PROTOCOL.md`。

> **見出しの選定:** Question #001 は、人道的大義（難民の経済的自立・AI高齢者ケア）であってはならない——遅く・dignity リスク最大・閉じない。**#001 は、Dan-Go の高 TTFR 第一候補（特に C3 国内の食料/生活困窮支援、次点 C4 国内難民の言語/法的支援・C7 教育）から採った、*最小の一件*——既存運営組織が当事者との同意を既に持ち、WAZIS/Dan-Go は個人に一切触れず、組織/観察者が受領・利用を記録でき、失敗しても誰も傷つかない micro-貢献**にすべき。5基準で **C3 が全軸最良**。最終確定には実在組織の稼働を人間が検証する一手だけが残る（捏造しない）。

---

## 1. Question #001 が持つべき特性

- **最小で境界づけられた実験**——日〜週で閉じる一件。「食料不安を解決」でなく「*この*公開要請に*この*具体貢献が応えるか」。
- **組織媒介・個人非接触**——既存の運営組織が当事者との同意関係を既に持ち、その組織を経由する。**WAZIS も Dan-Go も個人に直接触れない**（Dan-Go の鉄則・dignity）。
- **低障壁（国内/近接）**——言語・移動・封鎖・戦災の障壁が無い（feedback が安全に得られる）。
- **観測明瞭な Reality Feedback**——「貢献が届いた/使われたか」を組織または観察者が記録できる（executed/partial/failed が判別可能）。
- **失敗時安全**——失敗しても誰も傷つかず、その failure 自体が valid な RF。
- **Dan-Go 実行可能**——Voice→Gateway→Contribution→Execution に綺麗に写る*具体的な貢献型*（漠然とした願望でない）。
- **本物だが小さい**——わずかでも実在の救済に触れる（demonstrability のため）。だが grand でない。
- **同意が真正で到達可能**——組織レベルで取れる。**「助かった」の判定は当事者が組織経由で行う**（WAZIS が測らない・TTFR「本人の定義する形で」）。
- **dignity 安全**——憲法チェック通過（尊厳侵害なし・強制なし）。

---

## 2. Question #001 が避けるべき特性

- **大義/系統的**（難民の経済的自立・AI高齢者ケア）——大きすぎ・遅すぎ・閉じない（失敗様式 #2「無害なまま誰も助けない」）。
- **個人直接接触/脆弱な個人**——dignity・consent 複雑度が最大（Dan-Go が禁止）。
- **戦災/到達不能地**（Gaza/Sudan/Ukraine＝C2/C5/C6）——代理 feedback のみ・RF 不明瞭。
- **観測不能な漠然とした願望**——RF が明瞭にならない。
- **新 binding を要するもの**——具体 binding は Dan-Go のみ。**Dan-Go 実行可能**でなければならない。
- **失敗が実害を生むもの**——安全ゲートを通らない。
- **メタ問い**（現状 `docs/genesis-issue-1.md`「最初にどの問いを選ぶか」）——それ自体は現実に渡せず RF を生まない。
- **Reach Gap 中心**（安全ゲートを通れない最困窮の声）——**最終目標だが #001 ではない**（安全に閉じられない。§6）。

---

## 3. 評価基準（5軸・定義）

| 基準 | 望ましい向き | 「良い」とは |
|---|---|---|
| **Time To First Closed Loop（TTFCL）** | 短 | 日〜週で Question→RF→New Question が閉じる |
| **Dignity Risk** | 低 | 脆弱な個人に直接触れない・失敗時安全・強制なし |
| **Consent Complexity** | 低 | 既存組織が当事者同意を保持・組織レベルで完結 |
| **Reality Feedback Clarity** | 高 | 受領/利用を観測でき、executed/partial/failed が判別可能 |
| **Public Demonstrability** | 高 | 実在の救済に触れ、kernel が現実で走ったと公に示せる |

## 5. 選定（recommendation）

**Question #001 ＝ Dan-Go の C3（国内の食料/生活困窮支援。例: 既存フードバンク／子ども食堂ネットワークの*公開要請*）から採った、最小の一件。**

WAZIS オブジェクトへの写像（既存構造のみ・再設計なし）:
```
Question #001（開いた問い・公開）
  例: 「この公開要請〔特定団体の特定の不足〕は、〔特定の具体貢献〕で満たせるか?」
   → handoff{ dignity-check ＋ 組織レベル consent ＋ Dan-Go Claim へ写像 }
   → Dan-Go: Voice 記録 → Gateway（実在団体・要稼働検証）→ Contribution → Execution（団体が現実で受領/利用）
   → Reality Feedback（団体/観察者の記録・outcome 任意。failed でも成立）
   → New Question（その結果が開く次の問い）
```

なぜ C3 か（5基準の要約）: **TTFCL 最短**（国内・既存団体・一周が安全に成立しやすい＝Dan-Go の TTFR 検証価値「高」）／**Dignity Risk 最低**（組織媒介・個人非接触）／**Consent Complexity 最低**（団体が当事者同意を既に保持）／**RF Clarity 高**（受領/利用を団体が記録）／**Public Demo 高**（国内の実在の救済に触れる・具体）。

**残る唯一の確定手順（人間が行う・捏造しない）:** Dan-Go `FIRST_CASE_CANDIDATES.md` §「次にやること」に従い、(1) C3 の*現行の*公開要請 URL と運営団体の稼働を人間が確認、(2) 確認できた一件を Voice として記録、(3) 団体を Gateway 登録（稼働/未検証を正直に明記）。**私（AI）は団体の稼働を断定しない**（知識カットオフ・未検証）。WAZIS #001 ＝ この検証済み C3 一件に揃える（WAZIS の TTFCL ＝ Dan-Go の TTFR を一致させる）。

**fallback（5b）:** 今週どの C3 組織接続も確保できない場合に限り、自己/参加者実験で**まず機械的に一周を閉じる**——ただし「ループは証明するが救済の demonstrability は弱い」と正直に表示し、次の #002 で C3 に進む。

---

## 6. 正直な限界（隠さない）

- **#001 は Reach Gap を解決しない。** 安全ゲート（公開出典・個人非接触・失敗時安全）を通る候補は、最も孤立した最困窮の声を**含まない**——それが Reach Gap の中心（Dan-Go が明記）。**#001 は「ループが現実で閉じる」ことを証明するのであって、最難ケースを助けるのではない。** これを overselling しない。
- **すべて未検証。** C3 含め、団体の稼働・URL は人間が現実確認するまで断定しない。
- **「助かった」は WAZIS が測らない。** 当事者が組織経由で判定する（TTFR・想い非測定）。#001 の RF は「貢献が届いた/使われたか」の観測であって、満足度スコアではない。

---

## 7. Question #001 が *でない* もの

- 現状の `docs/genesis-issue-1.md`（メタ問い）——それ自体は RF を生まない。**#001 は閉じられる具体実験に差し替える。**
- 難民の経済的自立・AI 高齢者ケア——Commons の正当な*早期 Question* ではあるが、**TTFCL を証明する #001 ではない**（§4）。
- 共同体規模の問い——早期 Question 可だが最小でない。

---

## 8. 統合（一文で）

**Question #001 は、難民の経済的自立でも AI 高齢者ケアでも共同体規模の問いでもなく（いずれも大きすぎ・遅すぎ・dignity リスクが高く、最初の一周には不適）、Dan-Go の高 TTFR 第一候補——特に C3 国内の食料/生活困窮支援、次点 C4 国内難民の言語/法的支援・C7 教育——から採った*最小の一件*であって、既存運営組織が当事者との同意を既に保持し、WAZIS も Dan-Go も個人に一切触れず、組織または観察者が受領/利用を記録でき、失敗しても誰も傷つかない micro-貢献であり、5基準（TTFCL 短・Dignity Risk 低・Consent Complexity 低・RF Clarity 高・Public Demo 高）で C3 が全軸最良；残る唯一の作業は AI でなく人間が C3 の現行公開要請と団体稼働を検証して一件に確定することだけであり（私は稼働を断定しない）、それが取れなければ自己/参加者実験でまず機械的に一周を閉じる——いずれにせよ #001 は Reach Gap を解決せず、ループが現実で閉じることを証明するだけである。足すべき機能も概念も無い。**
