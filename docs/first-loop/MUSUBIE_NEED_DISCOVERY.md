# Musubie Need Discovery / むすびえの実需発見

- Date: 2026-06-22
- Scope: #001B の相手＝むすびえ。**30 日で `Question → Dan-Go Claim → Contribution → Reality Feedback` を一周できる、最小で公開済み・現に稼働中のニーズ**を同定する
- 種別: **リサーチ＋評価のみ**。実装・コード・既存ファイル修正を含まない。
- 規律: Dan-Go/WAZIS を再設計しない・最小観測ループを優先・仮説でなく実需。**Reality Feedback が目標、scale でない。**
- 方法: 2026-06 web 検証。**特定キャンペーンの現況は人間が最終確認**（私は稼働を断定しない）。

> **見出しの推奨:** **チャリボン（本で寄付）**——むすびえの公開・常設チャネルで、読み終えた本（5冊〜・ISBN 有・2010 年以降）を送ると ValueBooks が買取り、その額がむすびえへ寄付され、**買取/寄付の明細が報告として返る**。これが **6 基準すべてで最良**：specific（受理基準が明確）・consent 明瞭（公開常設の明示要請）・dignity 最低（古本・個人非接触）・**RF が clean な報告（受理冊数＋寄付額）**・TTFCL 最短（送付→報告で数日〜2週）・公開記録可能。**救済をより直接に出したいなら次点＝物資仲介（高ニーズ食材）**だが、企業向け・仲介マッチングで RF が遅い。

## 2. Top 5 候補ニーズ

1. **チャリボン（本で寄付）** — 読了本 5 冊〜を送付し寄付化。**need＝むすびえの常設「本での寄付」要請**。
2. **物資仲介：高ニーズ食材**（米/インスタント/レトルト/缶詰 等）を提供 — **need＝こども食堂の食材不足**。
3. **物資仲介：絵本/文房具** — **need＝子どもが楽しむ絵本・文房具の不足**（「子どもの喜び」に直結）。
4. **モノ寄付（総合窓口経由の物品寄付）** — チャリボン/物資仲介に重なる定義済みチャネル。
5. **単発寄付（任意額の金銭）** — 最速・最易だが specific でない（fallback）。

## 4. ランキング根拠

**チャリボン > 物資仲介:食材 ≈ 物資仲介:絵本 > モノ寄付 > 単発寄付。**

- **#001B で決定的なのは RF clarity ＋ TTFCL ＋ specificity**（30 日で clean に観測可能な一周）。
- **チャリボンが唯一、6 基準のうち 5 つで ★★★。** 個人で完結し、**買取/寄付の明細という discrete な RF 報告**が返り、受理基準が明確で、送付→報告が最短。しかも**受理基準（ISBN・年代・状態）ゆえ自然に `partial`/`failed` も生じうる**（一部買取不可）——「どの outcome も valid」を地で示せる。
- **物資仲介（#2/#3）は救済がより直接**（こども食堂が実際の食材/絵本を得る）だが、**企業向け＋仲介マッチング**で RF が遅く discrete でない。**「最初の RF を最小で安全に得る」より「救済の直接性」を優先するなら #2。**
- モノ寄付は #1/#2 に重複。単発寄付は最速だが specific でなく「need に答えた」感が弱い。

## 5. 推奨 #001B ニーズ

**推奨: チャリボン（本で寄付）。**

inner question（既存構造のみ・再設計なし）:
> **「むすびえの常設『本で寄付（チャリボン）』ニーズは、Dan-Go 経由（`funding` 現物：本）で満たされ、買取/寄付明細で確認されるか?」**

- **Dan-Go 写像:** Claim「むすびえのチャリボン・ニーズを満たす（N 冊を寄付化）」→ Contribution（`funding` 現物：読了本を送付）→ Execution（ValueBooks 買取→むすびえへ寄付）→ **Reality Feedback（買取/寄付明細：受理冊数・寄付額）**。
- **process RF:** 6 ステップ（Question→handoff→Claim→Contribution→RF→New Question）が公開記録。
- **need RF:** 明細＝むすびえへの寄付が観測可能に成立。**`executed`（全冊受理・寄付）/`partial`（一部受理）/`failed`（受理ゼロ＝ISBN/年代/状態不適）**——どれも valid。
- **30 日:** 送付→受理→明細で数日〜2 週。余裕。
- **公開観測:** 送付追跡＋明細を公開記録可。むすびえはチャリボン・キャンペーンを公開告知（公開チャネルとして可視）。
- **Question #002（outcome 別）:** 受理 →「この寄付はこども食堂に実際に使われ子どもに届いたか?」or「**Dan-Go 以外の binding**で同型の現物寄付を運べるか?」（中立性・U2）／部分 →「何が受理されず、貢献をどう精緻化するか?」／受理ゼロ →「受理基準に合う本をどう揃えるか／別チャネルか?」／チャネル休止 →「Dan-Go が現物寄付を route する最小条件は?」（infra）。

**残る唯一の人間作業:** [charibon.jp/guide](https://www.charibon.jp/guide/) と [musubie.org/monokifu](https://musubie.org/monokifu) で**現行の受理条件・キャンペーン有無を確認**し、送る本（5冊〜、ISBN 有/2010 年以降）を用意して WAZIS Question #001B の inner experiment として記録する。私は現況を断定しない。

**代替:** 救済の直接性を優先するなら **物資仲介：高ニーズ食材**（米/インスタント 等）を [musubie.org/activity/agency](https://musubie.org/activity/agency) の問い合わせ経由で。ただし企業向け・マッチング latency に留意。

---

## 6. 正直な限界（隠さない）

- **web 検証は 2026-06。受理基準・キャンペーン・物資仲介の現況は人間が最終確認**（条件は変わりうる）。
- **benefit は org レベルで究極受益者でない**（「本が寄付化されむすびえに届く」≠「特定の子どもが助かった」）。後者は #002 以降。一段手前で止めるのが dignity 安全の*手段*。
- **チャリボンは現物→金銭の変換（ValueBooks 仲介）を含む**＝一段間接。最直接を望むなら物資仲介だが RF が遅い（トレードオフ）。
- **「使われた/助かった」は WAZIS が測らない**——むすびえ/明細が確認する（想い非測定・RF は個別観測であって集計でない）。
- **Reach Gap は解決しない**。

---

## 7. 統合（一文で）

**むすびえの公開・稼働中チャネルを 6 基準で評価した結果、#001B の最小ニーズはチャリボン（本で寄付）が最良である——個人で完結し、受理基準が明確（specific）で公開常設（consent 明瞭）、古本ゆえ個人非接触（dignity 最低）、買取/寄付明細という discrete な Reality Feedback が数日〜2 週で返り（RF clarity ＋ TTFCL 最良）、受理基準ゆえ `partial`/`failed` も自然に生じて「どの outcome も valid」を地で示せ、Dan-Go の `funding`（現物：本）に綺麗に写る；救済の直接性を優先するなら次点＝物資仲介の高ニーズ食材だが企業向け・マッチング latency で RF が遅く、残る唯一の作業は AI でなく人間が charibon.jp/guide と musubie.org/monokifu で現行条件を確認し送る本を用意することだけである。足すべき機能・概念・scale は無い——目標は Reality Feedback であって規模でない。**
